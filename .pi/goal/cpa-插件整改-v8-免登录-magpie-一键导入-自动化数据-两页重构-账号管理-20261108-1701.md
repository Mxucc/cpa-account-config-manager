## Goal

在 `cpa-account-config-manager` 插件上解决线上实测暴露的五类问题，并把修复按「提交 → tag+1 → CI 构建 → 部署到 https://cpaous.256.ltd → 在线复测」的节奏交付：

1. **v8 免登录**：从 CLIProxyAPI v8 Management Center 打开插件页面时，若管理中心已有会话，插件必须直接进入总览，不再要求手输管理密钥。
2. **Magpie 一键导入**：供应商页的插件导入改为拉取 Magpie 社区插件仓库列表并一键导入，客户不再需要手填 `package.json`；manifest 由插件服务端拉取，浏览器不直接访问外网。
3. **自动化报错**：自动化「巡检」不再出现「服务端返回的数据结构无效，已保留当前页面数据，请稍后重试」，巡检结果表能正常渲染。
4. **界面重构**：自动化、日志与设置两个菜单下的界面用新设计系统（`web/src/ui/kit.tsx` + v2 样式）重做，不再内嵌旧组件；旧界面里的额外子页按用户选择并入新界面（自动化放 策略/通知/重试/代理，设置放 实验性功能/插件配置）。
5. **账号管理**：账号页恢复管理能力 —— 编辑配置、改模型、测试模型、刷新令牌、删除（含批量/去重预览）、导入账号、导出账号，导出/导入在页面上可见可操作。

## Acceptance criteria

每一项都要有可复现的命令或可观测行为作为证据，证据写入 `.web-builder/evidence/`（不提交到 git）。

1. **免登录**
   - `cd web && npx vitest run src/store` 全绿，且新增用例覆盖 Management Center 的 `managementKey`/`apiBase` 两种存储格式（`enc::v2::` 与 `enc::v1::`）与旧 `cli-proxy-auth` 回退。
   - 在 https://cpaous.256.ltd 同源写入管理中心会话（`managementKey`、`apiBase`），用 Playwright 打开 `/v0/resource/plugins/cpa-account-config-manager/index.html`：不输入任何密钥即渲染「总览」，且无 401、无控制台错误。截图入库。
   - 管理中心会话缺失时仍显示登录页（不能变成无鉴权直通）。

2. **Magpie 一键导入**
   - 新增只读接口 `GET /providers/market`：返回可导入的 Magpie/OpenCode 社区插件列表（含 id、名称、版本、来源），并有 5 分钟级缓存；未联网时返回空列表 + 原因，不抛 500。
   - `POST /providers/import` 支持按 `source=magpie-registry` + 插件 id 导入：服务端自行拉取该插件 manifest 并登记定义，浏览器不直接请求外网。
   - 线上验证：`GET .../providers/market` 至少返回 1 个插件；导入其中一个后 `GET .../providers` 出现该供应商，且 `/providers` 页面能用一次点击完成导入；截图入库。
   - 手动粘贴 manifest 的入口保留为高级选项。

3. **自动化数据结构**
   - `GET .../inspection/results` 不再返回「已存在但为空字符串」的枚举字段（`health`/`reason_code`/`confidence`/`recommendation`）；从未巡检的占位记录不再混入结果页，或字段缺失而非空串。
   - 客户端对空串字段做兼容处理（有 vitest 用例覆盖）。
   - 线上验证：打开自动化 → 巡检，页面不再出现该报错文案，结果表渲染出行；截图入库。

4. **两页重构**
   - `grep -rn "components/" web/src/v2/pages/*.tsx web/src/v2/pages/**/*.tsx` 不再出现旧组件导入。
   - 自动化页：巡检 / 策略 / 外部通知 / 自动重试 / 代理档案；日志与设置页：通用设置 / 操作日志 / 风险控制 / 实验性功能 / 插件配置 / 更新。每个子页都有加载、空、错误三态与确认步骤（破坏性操作）。
   - 线上逐子页走查：0 控制台错误、0 个 4xx/5xx 接口调用，截图入库。

5. **账号管理**
   - 账号页提供并可用：编辑配置、模型、测试、刷新令牌、删除（单条 + 批量预览/执行）、导入账号、导出账号（json/csv/jsonl）。
   - 线上验证：打开每个对话框并完成至少一次只读操作（如模型目录预览、导出下载、删除预览），记录请求与结果；截图入库。

6. **发布与部署**
   - 仓库干净提交（除 `.pi/`、`.web-builder/` 等会话产物），annotated tag 从 `v0.3.1475` 起每轮 +1。
   - GitHub Actions `CI` 与 `Release Plugin` 两套都 success，release 含 4 平台 zip + checksums。
   - 远程主机通过插件商店/自更新路径升到新版本：`GET /v0/management/plugins` 报告 `version` 为最新 tag、`supports_quota: true`；UI 资源为最新构建。

7. **回归**
   - `make verify` 退出码 0；`gofmt -l .` 为空；`go vet` 干净；`cd web && npx tsc -b --noEmit` 干净；`npx vitest run` 全绿；现有 legacy 兼容标签页（兼容（旧界面））仍可打开。

## Boundaries

- 不改统一域语义：未知一律 `null`、百分比与金额分开、窗口归一化（rolling/weekly/monthly）、状态优先级不变。
- 绝不接管 CPA 请求路由；Magpie sidecar 只读登录声明/模型目录/额度钩子，永不调用 `fetch`。
- 保留全部既有管理路由与三个 legacy 工作区（作为「兼容（旧界面）」标签）。
- 不记录、不持久化、不在界面或证据里输出任何密钥/token/凭据。
- 不动无关业务代码（巡检、通知、风控、自更新的内部语义只在本次五类问题范围内改动）。
- Bun / Playwright / 线上 CPA 任一不可用时就写「未验证」，绝不编造证据。
- tag 命名保持 `v0.3.N` 且只递增，不回滚、不覆盖已发布 tag。
- 部署只走宿主自身提供的插件商店/自更新接口，不做手工文件替换以外的绕过。
