# CPA 账号管理器 v2 实施计划

## 1. 目标与判定标准

本计划交付四件事，按顺序落地、每个 sprint 独立验收：

1. **兼容 CLIProxyAPI v8.0.60 与新 Management Center 前端**：插件 ABI schema 升到 10，新增 QuotaProvider、多登录入口、多供应商模型注册；管理配置写入优先走 v8（带 ETag），v0 保留回退。
2. **统一供应商域模型**：把 Codex / OpenCode Go / OpenCode Zen / Cline Pass / AI Provider 渠道收敛到同一套 `Provider → Account → Plan/Subscription → QuotaWindow → Billing` 模型，后端一处计算、前端一处渲染。
3. **用 web-builder 重写界面**：企业简洁风（Corporate Clean），12 个零散视图重组为 8 个主视图 + 供应商详情页；同一账号动作（新增/编辑/删除/刷新/测试/绑定/登录）在所有供应商上行为一致。
4. **Magpie 供应商插件兼容（分阶段、可降级）**：先做清单导入，再在 Bun 可用时通过 sidecar 执行 `auth` / `provider.models` / `auth.usage` 钩子；不可用时明确降级，不假装兼容。

**通过标准**：`make verify` 全绿（含 `go test -race ./...`、前端 typecheck/测试/构建）；新页面在 1440px 与 390px 无横向溢出；每个账号都能看到统一字段；未知额度显示“未上报”而不是 0；新 Management Center 的插件额度卡和登录入口能读到本插件数据。

## 2. 已核实的外部事实（不是猜测）

- 上游最新 Release：`router-for-me/CLIProxyAPI v8.0.60`（2026-11-07）。v0 Management API 仍支持，同时新增 `/v8/management`。
- v8 配置树：`/v8/management/config/api-keys/<kind>`；`PUT/PATCH` 支持 `If-Match` ETag，冲突返回 412。插件目前写的是 `PUT /v0/management/openai-compatibility` 等旧路径。
- 插件 RPC schema 当前为 **10**：v9 支持一次注册多供应商模型（`registrations`），v10 支持多 OAuth/auth 入口（`identifiers` / `entries`）。
- 插件能力表新增 `quota_provider`；方法为 `quota.identifier` / `quota.describe` / `quota.fetch` / `quota.reset`，响应结构是 `QuotaFetchResponse{subscription, summary, groups[{displayName,buckets[{window,remainingFraction,resetTime,description}]}], serverTimeOffsetMs}`。
- 新 Management Center 已实现并测试：插件列表字段 `supports_quota` / `quota_provider`、`supports_oauth` / `oauth_providers` / `oauth_provider_entries`；额度页对插件发 `POST /v8/management/plugins/<id>/quota {auth_index}`；资源页以 iframe 加载插件页面。
- Magpie 为 MIT；其供应商插件是 OpenCode 风格 npm 包（`auth`、`provider.models`、`fetch`、`auth.usage` 钩子），由 `internal/plugin/host.js`（3546 行）在 Bun 下以 JSON-line RPC 运行。本机 Bun 1.3.13 可用。
- 当前仓库基线：101 个 Go 测试文件 / 约 1105 个测试点；50 个前端测试文件 / 约 450 个测试点；`App.tsx` 1799 行、`types.ts` 1951 行、`styles.css` 3317 行；三个供应商页面分别 800/1266/1149 行，逻辑重复。

## 3. 总体架构

### 3.1 后端：新增 `internal/provider` 统一域

新增包（不重写现有 manager 逻辑，适配器调用已有服务）：

```text
internal/provider/
  definition.go      ProviderDefinition / Capabilities / AuthMode / 注册表
  account.go         规范化 Account / Plan / QuotaWindow / Billing / Credential / Status
  normalize.go       窗口、周期、金额、时区归一化（唯一计算入口）
  adapter.go         Adapter 接口与错误分类
  adapter_codex.go   适配 accounts/quota_metadata/codex_* 
  adapter_opencode.go 适配 opencode_*（Go + Zen）
  adapter_clinepass.go 适配 cline_pass_*（余额 + 5h/周/月 + 订阅）
  adapter_aiprovider.go 适配现有 AI Provider 渠道
  service.go         聚合、筛选、刷新编排、并发上限
  host_quota.go      QuotaProvider 能力实现
  host_auth.go       多登录入口与 auth.identifier
  host_models.go     多供应商模型注册
  registry_test.go / normalize_test.go / host_quota_test.go / adapters_test.go
```

**规范化 JSON（新 API 与前端共用）**：

```json
{
  "id": "provider:codex:acct-1",
  "provider": {"id": "codex", "kind": "oauth", "display_name": "Codex"},
  "display_name": "a***@example.com",
  "status": "ready|quota_limited|credential_invalid|disabled|unknown",
  "credential": {"configured": true, "expires_at": "...", "refreshable": true, "repairing": false},
  "plan": {"id": "plus", "name": "ChatGPT Plus", "tier": "plus",
           "cycle": {"kind": "monthly|rolling|weekly|none", "starts_at": "...", "renews_at": "...", "resets_at": "..."},
           "price": {"amount": 20, "currency": "USD", "source": "catalog"}},
  "quota": [
    {"id":"five_hour","label":"5 小时","kind":"rolling","used_percent":42,"remaining_percent":58,
     "limit":null,"unit":"%","reset_at":"...","aside":false,"source":"host"},
    {"id":"seven_day","label":"7 天","kind":"weekly","used_percent":71,"remaining_percent":29,
     "limit":null,"unit":"%","reset_at":"...","aside":false,"source":"host"}
  ],
  "billing": {"mode":"subscription|metered|unknown","currency":"USD","allowance":10,
              "used":3.2,"remaining":6.8,"period":"month","rate_source":"pricing-snapshot"},
  "usage": {"input_tokens":0,"output_tokens":0,"total_tokens":0,"cost_usd":0},
  "models": {"count": 12, "source": "upstream|catalog|plugin"},
  "binding": {"kind":"openai-compatibility","channel":"opencode","published":true},
  "source": {"kind":"cpa-auth|plugin-store|channel","ref":"..."},
  "updated_at": "..."
}
```

规则（写进 `normalize.go` 与表驱动测试）：

- **百分比与金额分开**：`used_percent` 只在宿主上报百分比时出现；`allowance/used/remaining` 只在有金额/额度时出现；未知一律 `null`，禁止用 0 冒充。
- **窗口归一**：Codex `five_hour/seven_day`、OpenCode `rolling/weekly/monthly`、Cline Pass `5h/weekly/monthly` 映射到统一 `kind`（`rolling/weekly/monthly`），保留原始 `source_window`。
- **订阅周期**：月付按 `renews_at`；Go 的 `$10/月` 拆 20%/50%/100% 三窗（写进 `Billing` 与 `QuotaWindow.limit`）；Cline Pass 以网关 `/plan/usage-limits` 为准；拿不到周期时 `cycle.kind="none"`，不推断。
- **重置时间**：统一 RFC3339；跨时区只做 instant 比较；DST/月底单独用例。
- **状态机**：`credential_invalid` > `quota_limited` > `disabled` > `ready`；Cline Pass 自动修复中显示 `repairing`，不静默降级。
- **密钥**：Account 只暴露掩码、是否已配置、过期时间；任何 token/cookie/key 不进公开模型、日志和测试夹具。

### 3.2 新统一 API（保留旧路由）

在 `internal/manager/app.go` 注册（路径前缀沿用 `managementRoutePrefix`）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |

### 3.3 新前端信息架构

8 个主视图 + 详情：

1. **总览**：账号总数、可用/受限/失效、订阅支出、额度热点、最近操作。
2. **账号**：唯一账号表；供应商 facet、计划、额度条、计费模式、状态、操作菜单。
3. **供应商**：注册表卡片（Codex / OpenCode Go / OpenCode Zen / Cline Pass / AI Provider / Magpie 插件）。
4. **额度与计划**：所有账号的窗口、重置时间线、订阅周期、钱包余额、未知值说明。
5. **用量与计费**：metered/subscription 分账、模型价格、账户成本。
6. **路由与模型**：渠道绑定、模型开关、价格来源、模型测试。
7. **自动化**：巡检、通知、策略、重试、代理。
8. **日志与设置**：操作日志、插件更新、实验性功能、风险控制入口。

供应商详情页固定 Tab：`账号 / 额度与计划 / 模型与价格 / 路由 / 高级`。Codex 指纹与身份策略、OpenCode 会话粘性、Cline Pass 自动修复都放进“高级”，不再各占一个顶层菜单。

**设计系统**（严格按用户给的 Corporate Clean 提示词）：

- 引入 Tailwind v3 + `clsx`，保留 CSS 变量做明暗主题；禁止 `rounded-none`、`shadow-2xl`、`border-4`、`bg-gradient-*`、`text-neon`。
- 基础件：`Button`（`rounded-lg shadow-sm hover:-translate-y-0.5 active:scale-[0.98] focus:ring-2 focus:ring-blue-500 focus:ring-offset-2`）、`Card`（`bg-white rounded-xl shadow-sm border border-gray-200 p-6`）、`Input`、`Select`、`Badge`、`Tabs`、`Table`、`Dialog`、`Drawer`、`Toast`、`Progress`、`EmptyState`、`Skeleton`、`PageHeader`、`Toolbar`。
- 动效 `duration-150/200 ease-out`，提供 `prefers-reduced-motion` 降级。
- 新增 `web/src/ui/styleContract.test.ts`：扫描所有 TSX，命中禁用 class 或缺少焦点/按压规则即失败；防止风格漂移。
- 路由：轻量 hash router（`#/accounts`、`#/providers/codex`），支持 iframe 深链与刷新保持。

## 4. CPA v8 / 新前端兼容细节

### 4.1 ABI 与能力

- `internal/cpaapi/types.go`：`SchemaVersion` 2 → 10；新增 `ProviderModels`、`Registrations`、`Quota*` 结构、`AuthProviderEntry`、`Identifiers/Entries`。
- `main.go`：处理 `quota.identifier/describe/fetch/reset`；`auth.identifier` 在 v10 下返回 `identifiers` 与 `entries`；`model.static` / `model.for_auth` 返回 `registrations`。
- `internal/manager/app.go` `RegistrationCapabilities`：新增 `quota_provider`、多登录入口与多供应商模型标志。
- 登录入口只注册**真实有宿主登录流程**的供应商：`codex-agent-identity`（现有）、`cline-pass`（设备码）。OpenCode Go/Zen 的 cookie/key 登录继续走插件页面，避免新前端出现点不动的卡片。
- QuotaProvider 的 `supported_providers` 只声明本插件实际托管的凭据类型；`supports_reset` 仅在 Codex 有可用 reset credit 时为 true。

### 4.2 管理 API v8 客户端

新增 `internal/manager/management_api_version.go`：

- 启动/首次写入时探测 `GET /v8/management/config`（404 → v0）。
- 渠道写入：v8 读 `config/api-keys/<kind>` → 合并且不覆盖他人字段 → `PATCH /v8/management/config/api-keys/<kind>`，带 `If-Match`；412 重读重试一次；仍冲突则返回可读错误，不盲目覆盖。
- `api-call`：优先 `/v8/management/requests/api-call`，回退 `/v0/management/api-call`。
- 所有请求仍走现有超时、密钥内存保存、脱敏与日志规则。

### 4.3 新前端额度契约

`quota.fetch` 返回：

- Codex：`groups=[{displayName:"额度", buckets:[5小时,7天]}]`，`subscription={plan:plan_type}`，`summary=[{key:"active_reset_count",...}]`，`serverTimeOffsetMs` 用响应 Date 与本地时钟差。
- OpenCode Go：三窗口 + `subscription={plan:"Go",tierName:"$10/月"}` + `summary=[月额度已用/剩余 USD]`。
- OpenCode Zen：`summary=[余额 USD]`（钱包），有窗口时照常给。
- Cline Pass：`summary=[余额 USD]` + 三窗口 + `subscription={plan:tier}`。
- 负数、NaN、越界百分比夹紧到 `[0,1]`；缺 reset 就不给字段；不允许 panic。

## 9. 风险、边界与需要确认

**风险**

- 这是跨后端域模型与整套 UI 的大改造；按 sprint 交付，任何单 sprint 不通过不进入下一 sprint。
- 外部契约可能继续演进；所有 v8/Management Center 逻辑集中在一个客户端与一个 quota 适配层，便于跟进。
- Magpie 插件是任意 JS；M2 只以 opt-in sidecar 运行，默认关闭，失败不影响原生供应商。
- 本机没有正在运行的 CPA v8 + Management Center 实例时，只能做 mock 契约测试与静态页面验证；会如实标注，不宣称端到端通过。

**非目标**

- 不重写 CPA 网关/路由/协议转换/执行器。
- 不实现真实支付、发票或第三方账单对接。
- 不承诺执行任意 magpie 插件的 `fetch`（路由仍归 CPA）；只兼容登录、模型目录、额度/用量钩子。
- 不保留旧 UI 的视觉结构；旧 URL 路由保留，旧 API 在迁移期保留。

**请确认的关键取舍**

1. 保持 React 18 + Vite + Tailwind（不换框架）。
2. 新 UI 默认浅色 Corporate Clean，同时保留明暗主题；不保留旧版信息架构。
3. Magpie 兼容按“清单导入必做、Bun 钩子执行可选”交付，不把完整 JS 运行时作为阻塞项。
4. 先交付 S1/S2（兼容与统一域），再交付 UI，避免在错误数据模型上重画界面。
